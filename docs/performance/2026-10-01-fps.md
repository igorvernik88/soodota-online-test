# FPS investigation, 2026-10-01

Synthetic measurements in Node on the same machine; these are CPU operation times, not measured browser FPS or GPU timings. Nine runs, median; 180 live creeps on separated sides, no opposing creep within attack radius, dt=0. Construction, puzzle generation and vision warm-up are excluded.

| Work | Before | After |
|---|---:|---:|
| All creepTick calls | 81.00 ms | 0.64 ms |
| Visibility calls in that batch | 17,280 | 0 |
| Four separation passes | 1.23 ms | 1.27 ms |

Reproduce current creep benchmark: `node scripts/benchmark-creep-tick.mjs`.

A separate 100,000-event history benchmark (21 runs, median) measured 0.6741 ms for the old full-array fireball filter and 0.0019 ms for the recent-tail lookup. Events are chronological; the replacement preserves their draw order and does not discard events used by other consumers.

## Changes

- Distance before visibility for creep and hero targets, and before objective-access checks for structures; remove the redundant first creep-target sort. Untouched-creep priority and tie order remain unchanged.
- Off-screen fog sources rejected before forest ray polygons, clipping and gradients. Bounds include the gradient fringe and 28 px of blur margin. Shared model vision remains unchanged.
- Off-screen creep sprites rejected before visibility and draw-list insertion, with a 180 sprite-scale margin for labels and death effects.
- Fireball rendering traverses only the recent event tail instead of the complete match history.

## Remaining candidates

- Four all-pairs separation passes remain quadratic. At 180 creeps this cost about 1.3 ms in this scenario, so no spatial-index rewrite or population limit was added.
- Visible moving sources still construct 128-ray forest polygons. The full-screen 24 px fog blur remains. Their actual graphics cost needs a live browser profile; culling is verified geometrically, not a measured GPU speedup.
- Vision refresh copies visible Sudoku pages every 100 ms. HUD refresh already runs at 10 Hz. Neither was changed without a attributable workload measurement.
- Dead creeps are removed after the existing short animation retention period; no permanent corpse accumulation was found. The offline asset bundle primarily affects startup/decode/memory, not evidence of per-frame CPU cost by itself.

## Checks

Before: 65/73 pass. After: 69/77 pass, adding four performance regressions, with the same eight pre-existing failures:

- armor absorbs exactly one hit from manual, universal, automatic and poison inputs
- tower stun prioritizes creeps, has an independent clock, and does not accumulate
- box at highest tier needs both independent pages with free input
- team spawn points stay separated inside healing range and persist through respawn
- heroes hold outside an active tower backdoor until creeps disable its armor
- combat animations play 1.3 times faster and running combat uses the requested sizes
- a hero uses the box animation only while trapped
- map geometry is converted once, with unchanged populations and local formations

No gameplay was altered to satisfy these expectations. UI and performance checks also run separately. Manual comparison should cover large waves, a moving camera near forest edges, entering/burning forest, fog reaching screen edges, creep death animations near the viewport border, and simultaneous fireballs.
